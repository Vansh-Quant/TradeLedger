## 1. Scope

This policy describes how TradeLedger may process information when a person uses its trading journal and related features. Update it before launch to cover every enabled feature, hosting provider, analytics tool, logging system, and integration.

## 2. Information that may be processed

Depending on enabled features and information a user enters, TradeLedger may process:

- Account information used for authentication, such as email address and authentication/session identifiers.
- Journal data entered by the user, including trade date, symbol, direction, setup, entry/exit values, quantity, profit/loss, notes, reflections, and optional chart screenshots.
- Technical and diagnostic information generated by the application or hosting provider, such as request logs, error details, device/browser metadata, and security events, where collected.
- Support messages and information a user voluntarily provides.

Do not enter broker passwords, exchange API secrets, payment-card information, or other credentials into journal fields.

## 3. Purposes

Information is used to authenticate users, store and display journal entries, calculate journal analytics, provide backup/export and import features, maintain security, troubleshoot failures, and respond to support requests. Disclose any additional purpose before that processing begins.

## 4. Storage and service providers

The hosted journal uses Supabase Auth and a Supabase Postgres table for journal records when hosted mode is configured. The application has also supported browser-local journal storage during local development. Browser-local records are separate from hosted records until the user explicitly imports them.

## 5. Access controls and security

Hosted journal rows are intended to be scoped to the authenticated owner using PostgreSQL Row Level Security (RLS). The operator must test these database policies directly before launch. A user-interface test alone is not proof of database isolation.

The operator should use least-privilege access, keep secret keys out of browser code and source control, maintain dependencies, and provide a process for reporting suspected security issues. No internet-connected service can guarantee absolute security.
